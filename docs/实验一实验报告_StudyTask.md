## 一、 实验目标与需求范围

### 1.1 实验目标
1. 掌握 AI 辅助编程工具的工作区管理、提示词工程与迭代交互规范；
2. 依据教师提供的完整《软件需求规格说明书》（SRS），驱动 AI 生成符合规范的单用户 Web 学习任务管理系统；
3. 掌握软件本地运行、功能用例逐项验收、缺陷精准报告与人机协同修复流程；
4. 明确 AI 在现代软件工程中承担的自动编码角色，与工程师必须恪守的验证、设计与质量把控责任。

### 1.2 需求范围与边界声明
- **核心范围（必做项）**：
  - 任务增删改查（名称 1~100 字、课程 1~60 字、截止日期 YYYY-MM-DD、优先级高/中/低）；
  - 任务状态三态流转（待完成 / 进行中 / 已完成）；
  - 多条件组合筛选（课程、状态、优先级任意组合）；
  - 逾期（早于今日未完成）与即将到期（今日起 3 天内未完成）动态高亮标记；
  - 任务看板数据统计（总数、已完成数、完成率）；
  - 本地 SQLite 持久化及重启一致性；
  - 全中文友好界面与错误阻断保护。
- **范围外边界（严格不实现）**：
  - 不实现用户注册/登录/多角色权限系统；
  - 不做外部邮件/短信推送、第三方日历同步与移动端 App。

## 二、 系统实现方案

### 2.1 技术选型与运行环境
- **操作系统**：Windows 11 / macOS / Linux 通用兼容
- **开发语言与环境**：Python 3.13 / 独立虚拟环境 `.venv`
- **后端架构**：Flask 3.1.3，采用轻量化 MVC 架构

## 三、 实施过程与 AI 人机协作记录

本项目遵循“**需求下达 $\rightarrow$ 人工审核方案 $\rightarrow$ 代码分步生成 $\rightarrow$ 自动化测试 $\rightarrow$ 人工审查缺陷与修复 $\rightarrow$ 最终封存**”的标准软件工程流程。

1. **版本 `v0.1-plan`**：向 AI 完整输入 SRS，要求先出具实施步骤和验收清单。AI 一度尝试增加“用户登录模块”，人工果断叫停并明确边界，避免需求蔓延。
2. **版本 `v0.2-model`**：AI 完成 `models.py` 的数据建模与基本 CRUD。人工代码审查时发现计算完成率时未做 `total == 0` 的守卫判断，存在除零崩溃隐患，要求 AI 修正。
3. **版本 `v0.3-view`**：生成前端界面。人工指出删除操作使用 GET 请求的安全隐患，要求重构为二次确认弹窗的 POST 表单。
4. **版本 `v0.4-test`**：编写 pytest 测试。在 Windows 下暴露出 SQLite 连接未显式 close 导致的文件锁占用错误，人工指导 AI 将所有数据库操作重构为 `try...finally: conn.close()`。
5. **版本 `v1.0-release`**：11 项自动化测试全绿通过，初始化演示数据，完成全部文档与交付归档。

## 五、 问题发现、修复过程与工程师反思

### 5.1 遇到的典型问题与修复过程

#### 问题 1：空数据状态下的除零隐患（ZeroDivisionError）
- **问题定位**：AI 在初始生成 `get_statistics()` 时，直接编写 `(completed / total) * 100`。在系统初始化无任何任务时，`total` 为 0，触发严重的 500 崩溃。
- **人工干预与修复**：人工审查发现后，指导 AI 编写了针对空库状态的专用用例 `test_case_zero_tasks_completion_rate`，并在底层逻辑中加入守卫分支：`if total == 0: return 0.0`，彻底解决空库可用性问题。

#### 问题 2：Windows 操作系统特有的 SQLite 句柄文件锁（WinError 32）
- **问题定位**：在自动化测试执行时，所有用例断言均通过，但在 fixture teardown 阶段发生批量崩溃（`PermissionError: [WinError 32] 另一个程序正在使用此文件`）。经深入分析，AI 编写的数据库操作仅依赖了 `with conn:` 语法糖，而该语法在 Python sqlite3 库中仅负责事务 commit，并未关闭底层句柄。在 Windows NTFS 文件系统严格的文件锁机制下，未释放句柄的文件直接导致 `os.remove` 失败。
- **人工干预与修复**：人工指出机制本质，要求 AI 全面重写所有数据库访问函数，统一采用 `try...finally: conn.close()` 范式，确保每个请求周期严格归还系统句柄，并在测试端立即关闭临时句柄。修改后 11 项用例瞬间全绿。

### 5.2 软件工程反思（回答指导书 5.3 核心问题）
1. **AI 擅长什么？**：AI 在快速代码脚手架生成、通用算法编写、基础 CSS 样式设计和用例模板编写方面表现出极高的生产力，将开发周期从数天压缩至数小时。
2. **AI 的盲区在哪里？**：AI 缺乏“运行环境上下文感”与“极值敏感度”。它容易生成看似语法正确但在特定操作系统（如 Windows 独占锁）、特定极端输入（除零、超长输入、并发竞争）下脆弱的代码。
3. **工程师的不可替代性**：工程师必须始终坚持“可用 AI，但必须可验证”的原则。工程师的核心价值在于**制定严密的规格说明、把控系统架构边界、设计严苛的验收体系，以及利用专业工程常识定位复杂环境缺陷**。
